# 架构与能力范围

服务把参考音色和文稿转换成可试听、可下载的音频。网页、REST 和 MCP 共用同一个 `SynthesisService`，任务与音色元数据保存在 SQLite，音频和缓存保存在本地目录。

## 处理流程

1. 注册参考 WAV，保存原始录音，并排队提取参考条件。
2. 将普通文本、导演稿 JSON 或 SSML 编译成执行计划，检查音色、参数与模型能力。
3. 将通过预检的请求加入持久化队列，由单个模型持有进程串行执行。
4. 使用 Qwen3-TTS 生成原始 WAV，再通过 Rubber Band 与 FFmpeg 处理数值控制、停顿和编码。
5. 组装整稿与逐页音频，保存输入原文、执行计划、时间轴和生成记录。

## 代码结构

| 模块 | 职责 |
| --- | --- |
| `app.py`、`server.py` | HTTP 接口、生命周期和启动入口。 |

| `mcp_server.py` | HTTP MCP 工具与资源。 |

## 模型适配

默认 `qwen-base` 使用官方参考音色克隆接口。完整参考模式 `icl` 需要录音对应文字；`x_vector_only` 仅使用说话人特征。当前推理后端限定单张 RTX 2080 Ti、FP16，显式选择设备，不提供 CPU 或多卡回退。

`qwen-custom` 使用 CustomVoice 预设音色，不接受参考录音。`qwen-combined-experimental` 尝试组合 Base 提取的说话人特征与 CustomVoice 表达条件，请求必须显式启用实验能力；参数路径成立不能证明音色相似度或表达效果。

容器仅暴露选定的一张 GPU，因此进程内的设备编号为 `cuda:0`。它与宿主机设备编号分别记录；运行时的设备信息不作为仓库示例数据。

默认注意力实现为 SDPA，生成调用使用 `torch.inference_mode()`。模型子进程在初始化模型前设置 `TORCH_NUM_THREADS` 和 `TORCH_NUM_INTEROP_THREADS`，默认各为 1；它们不改变持久化队列的串行执行方式。健康信息包含配置的线程预算和加载模型后实际使用的线程数，原始音频缓存的模型身份继续包含注意力实现。

`CUDA_GRAPH_ENABLED=1` 启用可选的子模型图回放路径：`backends/cuda_graph.py` 使用 Transformers 的 `StaticCache`，为 15 步残余编码预测预分配固定 KV、位置、因果掩码和输入输出缓冲。每帧回放前在图内重置 KV，外部输入复制到固定缓冲，输出复制后交给官方 Talker；文本、ICL、说话人条件、外层解码与终止判断仍走官方 SDK。只有当前模型实例的 predictor 调用在单次生成范围内被临时替换，退出或异常时恢复，不修改安装包或全局类。

图按采样开关、top-k、top-p 和温度配置，最多保留一套；参数变化会重新捕获。采样使用与固定 SDK 相同的 FP32 logits 和 Transformers warper 顺序，捕获与预热保存并恢复随机数状态。图回放可能改变 GPU 随机数的消耗方式，种子保证同一路径重复生成可复现，不保证与官方路径逐样本一致。图版本写入模型身份，避免跨执行路径复用条件或原始音频缓存。捕获失败会终止服务拥有的模型进程并报告错误；不自动更换执行路径、模型或设备。

## 原文、控制与缓存

- 原文与实际读法分别保留。发音替换会记录映射，不把表达指令读入正文。
- 语速、音高与增益由音频后处理完成，停顿为额外静音。不支持的控制在预检中报告，降级需要请求显式允许。
- 原生成、后处理和拼接分别缓存。仅调整数值控制可复用原始生成；缓存命中需要文件内容校验。
- 参考条件按音频、文字、模式、模型版本等信息隔离，使用禁用 pickle 的 NPZ 存储。
- 长稿按自然句或短段生成。时间轴基于实际音频帧与静音事件，不提供虚构的字级对齐。

## 任务与接口

任务状态为 `queued`、`running`、`succeeded`、`failed`、`cancelled`。取消在生成单元之间生效；调用超时只终止服务拥有的模型进程。重启后，旧运行任务标为失败，排队任务可恢复。

模型持有进程通过同一 RPC 通道发送段内解码进度，最多每 250 毫秒一次；父进程继续等待最终回复，进度事件不重置超时。`progress_detail` 保存阶段、片段位置、真实解码步数及由 codec 帧数换算的音频长度。段内比例按文稿长度估算，并明确标记 `estimated=true`；进度不会用 `MAX_NEW_TOKENS` 上限代替实际生成长度，也不按计时器虚增。

任务进度存入 SQLite，旧数据库自动增加可空的 `progress_detail` 列。执行中的数值保持单调，终态拒绝迟到更新；生成、后处理、拼接、编码和保存有各自的阶段，仅成功保存产物后到达 100%。网页对活动任务每 500 毫秒读取一次状态。

OpenAI 兼容 speech 接口使用同一队列并同步等待。长稿可使用异步配音接口，MCP 返回任务和产物链接，音频通过 HTTP 下载。

`/health` 报告服务存活状态，`/ready` 在模型与音频工具可用前返回 503。可选 Bearer 鉴权保护 `/v1/*` 与 `/mcp/`；管理 Token 为空时禁用管理入口。

快速复刻由非空 `ASR_BASE_URL` 与 `qwen-base` 后端共同启用。`/health.features.quick_voice_clone` 分别报告配置启用、后端兼容和 ASR 可用状态，后台每 30 秒检查一次 ASR；外部 ASR 不参与 TTS `/ready` 判断。

录音通过固定音频解码器转换为当前工作采样率的单声道 PCM WAV，解码输出限制为最多 31 秒，超过 30 秒的录音会拒绝而非截断。音频和草稿 JSON 位于 `data/reference-drafts/`，随机 ID、文件哈希和到期时间将录音绑定到用户确认的文字。ASR 只接收转换后的同一份 WAV；转写失败仍返回可用草稿与 `asr_error`。提交草稿必须提供非空文字并使用 ICL，复用 `voice_prepare` 队列与既有条件缓存。同一草稿的相同提交重试不会生成重复音色。

ASR 通过有超时、禁用环境代理与重定向的 HTTP 客户端访问，每个 TTS 服务最多一个转写请求在途；转写不占 TTS GPU 任务队列。临时草稿每 30 秒清理，识别中的草稿受保护；用户清除或草稿到期均不删除已经保存的音色。

## 数据与公开文档

`models/` 保存模型快照，`data/` 保存参考录音、条件、数据库、缓存与产物；两者均被 Git 和 Docker 构建上下文忽略。诊断结果和浏览器报告默认写入 `test-results/`。

公开文档与截图使用演示内容。真实配置、日志、设备标识、参考录音及运维记录应保存在忽略目录或仓库外，不作为发布附件。
